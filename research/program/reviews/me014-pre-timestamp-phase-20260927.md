The first implementation placed a pre-ingress hook after a coarse one-second `Advance`. The reviewer **rejected** its use as a `t⁻` frontier: a gateway order delivered at `t−500 ms` was merely queued by a scheduler callback and could not affect the book until after the hook at `t`. That would wrongly exclude an event strictly before funding or price sampling. This finding was not set aside or reclassified as a harmless timing detail.

The successor opt-in `DrainIntermediateEvents` mode now processes each scheduler event-time batch strictly before the step target and drains venue/actor phases to a fixed point before moving forward. The `BeforeTimestampPhase` callback runs after target-time scheduler callbacks but before venue jobs, ingress, egress and actor phase callbacks at the target. Synthetic tests cover earlier off-grid order execution, target-time queue-only order priority, an event scheduled by an intermediate drain, error propagation, detected direct clock mutation and the mode's configuration boundary. With the mode unset, the ordinary runner uses the prior path. Clean `GOMAXPROCS=4 GOFLAGS=-p=4 make test` passed at `00b63ec1`, including integrated and archive parity fixtures; `go vet ./...`, targeted simulation race and `git diff --check` passed. A precommit dirty-worktree `make test` passed Go/integrated fixtures but archive parity correctly refused the dirty tree.

The same reviewer then found that a public **concurrent clock advance** can still process later callbacks while the opt-in helper has released the clock lock. A concurrently inserted scheduler event can likewise arrive after its last empty-heap check. The later checks detect some clock movement after a callback or drain, but they do not prevent all effects. The reviewer therefore retained a conditional verdict, not a full acceptance of E2 funding order. The helper is usable only in an assembled world with one runner-owned clock advancer and phase-owned event producers; that ownership must be enforced or verified with source-grounded integration tests before an economic world. Direct book/position mutations from scheduler callbacks also remain outside the permitted E2 path. At initial time, actor `Start` runs before the hook and must only queue ordinary interface requests; no t=0 funding sample is justified by this hook.

The opt-in mode changes when off-grid events can affect subsequent actor decisions and books. It is a **new E2 timing semantic**, not observation-only instrumentation and not a retrospective correction of E0/E1 results. No E2 production sampler, two-venue joint epoch, account posting or canonical payment evidence is wired by this commit. E2 stays **PREPARE / NOT RUN-READY**; no economic or holdout process ran.
