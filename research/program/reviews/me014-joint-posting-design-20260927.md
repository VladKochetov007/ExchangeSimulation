# ME-014 joint posting fixture — prospective design review

Review execution: **COMPLETED** by a read-only Sol-6 medium reviewer who did not implement the design. Substantive verdict on the revised [prospective note](../ideas/ME-014/joint-posting-design-20260927.md): **NO REMAINING CONCEPTUAL ECONOMIC OR TRANSACTION AMBIGUITY FOR THE ISOLATED FIXTURE**. This is not an acceptance of implementation, production E2 settlement, a complete causal world or any economic result. No simulator world or holdout ran.

The reviewer first **did not approve** a generic “lock, preview, mutate” plan. The reserve had no verified USD source, the existing venue movement path would send an unknown bucket into fee revenue, and both the exchange conservation check and independent analyzer knew only fee/insurance buckets. A single-venue commit before the other venue's structural preflight would violate the joint epoch contract. Ordinary balance logging cannot roll back cash or guarantee required evidence.

The first written revision named a separate reserve bucket, an external endowment, both-venue preflight, state revalidation and an authoritative journal, but still left two choices ambiguous. The reviewer required (1) explicit cash/evidence order and invalidation on partial append/seal failure, and (2) reserve sizing against the frozen maximum roster `K`, not just today's active count. The final note chooses exact `K` USD atoms from `E2_ROUNDING_RESERVE_ENDOWMENT`, freezes all `K` identities at construction, prohibits top-ups/recycling, and specifies joint mutation followed by one required epoch append. Any append/seal failure freezes an invalid trajectory; there is no claimed rollback or crash-atomic durability. The reviewer found those choices conceptually sufficient for the isolated fixture.

Implementation acceptance must additionally reject a failed `0 → K` endowment recording **before** the fixture becomes usable. Tests must distinguish no-payment endowment, reserve versus fee income, stale state, structural abort, economic payer shortfall, journal failure/quarantine, and independent replay. The reviewed design has no source-code test result; those are future gates.
