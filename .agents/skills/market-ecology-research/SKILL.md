# Market-ecology research

Use one evidence-driven cycle for one bounded question or explicitly authorized batch.
The output is a conditional claim, a reproducible null, or a precise limitation.
A skill invocation is not authorization to run the registry.

## Start with the task and current state

1. Identify the requested mode, study ID, and owner instruction.
2. Read applicable AGENTS.md, research/README.md and research/program/README.md.
3. Locate the ID in research/program/registry.json and read its idea card.
4. Follow authoritative protocol/report links; do not create competing copies.
5. Verify branch, HEAD, dirty state, candidate identity and relevant concurrent work.
6. Read only the source/tests and historical summaries needed for this question.
7. Report missing artifacts as missing; do not replace them with a new run.
8. State the strongest intended claim and the smallest next authorized action.

Resolve paths from the repository root containing this skill, not a fixed machine path.
Use Git to resolve worktree metadata; preserve other agents' changes and checkouts.
Treat the registry as a finite queue, never as an autonomous execution schedule.
Explicit owner scope takes precedence over this skill's generic workflow.

## Modes are prompt conventions

| Mode | Work and stopping point |
|---|---|
| INTAKE | Locate idea, predecessors, code and evidence; identify the next bounded question. |
| PLAN | Specify mechanism, estimand, fixtures, finite matrix, budget and falsifier. |
| PREPARE | Implement only explicitly authorized readiness changes and relevant tests. |
| RUN | Execute only an explicitly authorized pinned protocol within its limits. |
| ANALYZE | Reconstruct authorized retained evidence; separate discovery from confirmation. |
| REPORT | Publish technical report and result record with exact claim/evidence links. |
| SYNTHESIZE | Compare completed studies with their population/version limitations. |

Default to INTAKE/PLAN when execution authority is absent.
Do not invent Codex command-line flags for these modes.
A mode authorizes no action beyond the user's actual instruction.
PREPARE does not automatically authorize economic worlds.
ANALYZE does not authorize opening untouched or reserved outcomes.

## Authorization and finite work

For RUN, bind the owner's authorization to study IDs and protocol revisions.
It must bound world count, seeds/conditions, horizon, resources and stop rules.
Record permitted follow-ups and the boundary for confirmation/frozen partitions.
Once a batch is authorized, proceed through its cells without repetitive permission requests.
Stop at its actual limits; unused quota or time does not authorize another idea.
A substantive new economic choice or changed protocol requires prospective authority.
Never reuse historical reserved holdout labels as convenient new development seeds.
Before allocating resources, inspect available memory/disk and concurrent work.
Account for peak staging, output and decompression volume, not only final storage.
Use real exit status, child placement and completeness checks from existing runners.
Do not lower requirements or delete protected evidence to make a gate pass.

## Claim type and state

Choose the strongest intended type:
MECHANICAL, DESCRIPTIVE, ACTIVATION, CAUSAL, REPLICATION, EMPIRICAL, GAME-THEORETIC.
These are claim types, not a compulsory ladder every study must climb.
Record study stage separately from process status and evidence validity.
Also separate opportunity presence, policy activity, registered activation,
causal verdict and empirical comparison.
A successful process does not prove valid evidence.
Valid evidence can establish a loss, null, non-activation or unavailable statistic.
No trades can be a rational policy response under the declared objective.
An absent opportunity does not prove failure to act on an opportunity.
A failure to reject is not proof of equivalence or zero effect.

## Apply the cycle proportionally

1. State one question and its strongest allowed conclusion.
2. Map historical evidence and distinguish new assumptions from old results.
3. State objectives, resources, information and economic mechanism.
4. Define formulas, units, valid domains and the opportunity/risk denominator.
5. Trace the actual production path; verify minimal counterexample fixtures.
6. If readiness fails, propose a localized fix or record missing capability.
7. Lock a bounded protocol and obtain review appropriate to the intended claim.
8. Execute only after the required owner authorization and candidate pin.
9. Independently reconstruct evidence before interpreting economics.
10. Estimate the registered contrast, retaining nulls and unsuccessful worlds.
11. Apply only preregistered ablation/replacement/restoration/robustness modules.
12. Confirm frozen claims on uninspected conditions only when authorized.
13. Publish report/result and stop at the authorized boundary.

The reference diagram describes reusable modules, not mandatory extra experiments.
Mark irrelevant modules N/A with a reason.
Do not add a gate after seeing outcomes or tune until the scoreboard is green.
Use calibration data honestly; it is no longer untouched validation.
A valid negative result licenses reporting, not an automatic rescue.

## Map entities before comparing them

Policy = algorithm, parameters and objective.
Actor = instance, endowments, liabilities and risk/financing budget.
Deployment = location, directed feed/order/response paths and computation model.
Venue = matching, fees, admission, market data and lifecycle.
Map existing fields to these concepts without demanding a platform refactor.
A policy name must not silently select a faster deployment.
Distinguish order instruction, venue allocation and routing.
Separate host capacity, executable quantity and economic capital capacity.

## Evidence and economic discipline

Trace scale to requests, orders, exposure, capital use and the objective.
Distinguish directly programmed equations from emergent market consequences.
Require independently derived arithmetic, rounding and counterexample checks.
Match fees to their charged assets and include residual/exit/financing costs.
Use executable depth and legal quantities for arbitrage claims.
A manufactured positive edge is a mechanical fixture, not discovered alpha.
Do not loosen missing-price or terminal-risk rules to obtain a result.
Join exchange event time and actor receipt time separately.
Never infer global event order from file traversal.
Preserve raw artifacts, invalid attempts, amendments and previous verdicts.
Keep the original trajectory source distinct from a corrected analyzer revision.

## Review without churn

Use bounded independent reviews for concrete mechanical/evidence and
causal/statistical risks when warranted; no whole-repository audit per idea.
Use an allowed fresh reviewer context that did not implement the candidate.
Respect owner model restrictions: Luna, Terra or Sol; never Astra.
Default to Luna xhigh when available and authorized.
Decide a bounded fallback before substantive verdicts: one permitted independent
fallback after an unavailable path, then one external review package.
An unavailable service is execution UNAVAILABLE and verdict NOT_ISSUED.
A crashed review is FAILED / NOT_ISSUED; neither is scientific rejection.
Resolve substantive rejection; do not switch reviewers to seek acceptance.
Do not self-approve or invent reviews.
Pin executable candidate C and governing protocol.
Keep later status/report commits separate; documentation does not move C.
Relevant executable/config/protocol amendments require scoped revalidation.
Reuse demonstrably applicable tests and existing manifests.
